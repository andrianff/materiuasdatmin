1. Pendahuluan

Analisis asosiasi (association rule mining) adalah teknik data mining untuk menemukan aturan asosiatif antara suatu kombinasi item.
  • Contoh: seberapa besar kemungkinan pelanggan membeli roti bersamaan dengan susu.
  • Terkenal lewat aplikasi analisis isi keranjang belanja di pasar swalayan → disebut juga market basket analysis.
  • Dicetuskan oleh Agrawal dkk. (1993).
  • Termasuk teknik dasar dari teknik data mining lain; tahap khususnya: analisis pola frekuensi tinggi (frequent pattern mining).

Manfaat bagi pemilik swalayan

  • Mengatur penempatan barang
  • Merancang kampanye pemasaran (kupon diskon untuk kombinasi barang tertentu)
  • dll.

2. Terminologi

Data historis (data latihan / training data, data pengalaman) dipakai algoritma untuk menemukan pengetahuan: item-item belanja yang sering dibeli secara bersamaan.

Penting-tidaknya aturan asosiatif diukur dengan dua parameter:

Support (nilai penunjang)
Persentase kombinasi item tersebut dalam database.
Confidence (nilai kepastian)
Kuatnya hubungan antar item dalam aturan asosiatif.

Bentuk aturan: "if … then …" / "jika … maka …".

Contoh: $\{\text{roti},\text{mentega}\}\rightarrow\{\text{susu}\}$ (support = 40%, confidence = 50%)
  • 50% dari transaksi yang memuat roti & mentega juga memuat susu.
  • 40% dari seluruh transaksi memuat ketiga item itu.

Analisis asosiasi = proses menemukan semua aturan asosiatif yang memenuhi syarat minimum support (minimum support) dan minimum confidence.

3. Metodologi: Support & Confidence

Dua tahap utama:

  1. Analisis pola frekuensi tinggi (frequent pattern mining) — cari kombinasi item yang memenuhi minimum support.
  2. Pembentukan aturan asosiatif — dari frequent itemset cari aturan yang memenuhi minimum confidence.
Support 1 item $$\text{Support}(A)=\frac{\text{Jumlah transaksi mengandung }A}{\text{Total transaksi}}$$
Support 2 item $$\text{Support}(A\cap B)=\frac{\text{Jumlah transaksi mengandung }A\text{ dan }B}{\text{Total transaksi}}$$
Confidence aturan A → B $$\text{Confidence}=P(B\mid A)=\frac{\text{Jumlah transaksi mengandung }A\text{ dan }B}{\text{Jumlah transaksi mengandung }A}$$

Bentuk setara (versi slide pembentukan aturan):

$$\text{SUPPORT}=\frac{\sum \text{item yang dibeli sekaligus}}{\sum \text{jumlah seluruh transaksi}}\times100\%$$ $$\text{CONFIDENCE}=\frac{\sum \text{item yang dibeli sekaligus}}{\sum \text{jumlah transaksi pada bagian antecedent}}\times100\%$$
Support penyebutnya = semua transaksi. Confidence penyebutnya = transaksi yang memuat antecedent. Support simetris ($A\to B$ sama dengan $B\to A$), confidence tidak simetris.

4. Algoritma Apriori

Langkah umum

  1. Tentukan $\Phi$ (minimum support count).
  2. Tentukan semua frequent item set.
  3. Untuk setiap frequent item set: ambil sebuah unsur $s$; sisanya $ss-s$; masukkan ke rule If ($ss-s$) then $s$. Lakukan untuk semua unsur.
Dalam slide: antecedent = $(ss-s)$ (bagian "if"), consequent = $s$ (bagian "then"). Antecedent boleh >1 unsur, consequent hanya 1 unsur.

Aturan Apriori (anti-monotone)

Prinsip Apriori Jika $Z$ bukan frequent itemset, maka $Z\cup A$ pasti bukan frequent itemset, untuk setiap $A$.

Dipakai untuk meringankan pencarian $F_3,F_4,F_5,\dots$ → candidate yang punya subset tidak frequent langsung dibuang (pruning).

Penggabungan (join) kandidat

  • Kombinasi itemset di $F_{k-1}$ digabung menjadi calon $k$-itemset.
  • Itemset yang digabung harus punya kesamaan pada item-item pertamanya (semua kecuali item terakhir). Mis. {A,B} dan {A,F} sama di item pertama A → jadi {A,B,F}.
Berhenti saat $F_k=\emptyset$. Kalau $F_3=\{\}$, maka $F_4,F_5,\dots$ otomatis kosong.

7. FP-Tree (Frequent Pattern Tree)

Mengapa FP-Tree?

  • Apriori kurang baik bila banyak frequent pattern, banyak jenis item, namun minimum support rendah.
  • Apriori lambat karena scanning database berulang-ulang.
  • FP-Tree dirancang mengatasi bottleneck penggalian data pada Apriori. Dicetuskan Zhao et al. (2003) (sesuai slide).

Ide / gagasan

  • Pemampatan data dengan struktur pohon → menghindari scanning database berulang.
  • Tidak memerlukan candidate generation.
  • Dilanjutkan algoritma FP-Growth yang langsung mengekstrak frequent itemset dari FP-Tree dengan prinsip divide and conquer.

Definisi FP-Tree

  • Terdiri atas root berlabel 'null', sekumpulan subtree sebagai child root, dan sebuah tabel frequent header.
  • Setiap node mengandung 3 informasi:
    1. label item – jenis item yang diwakili node,
    2. support count – jumlah lintasan transaksi yang melalui node,
    3. pointer penghubung – menghubungkan node berlabel sama antar-lintasan (garis panah putus-putus).
  • Tiap baris tabel frequent header = label item + head of nodelink (menunjuk node pertama berlabel item itu di FP-Tree).

Ukuran FP-Tree

  • Biasanya lebih kecil dari data asli (banyak transaksi berprefix sama).
  • Best case: semua transaksi berisi item sama → 1 path.
  • Worst case: tiap transaksi unik → ukuran = data asli, bahkan kebutuhan simpan lebih besar (pointer & counter).
  • Bergantung urutan item. Urut berdasar support menurun biasa dipakai, tapi tidak selalu menghasilkan tree terkecil (heuristik).

Dua tahap FP-Growth: (1) bentuk FP-Tree, (2) ekstrak frequent itemset dari FP-Tree dengan FP-Growth.

8. Membangun FP-Tree (Contoh min support count = 2)

Langkah: (1) scan database, hitung support tiap item; (2) buang item yang support < min (f, r, z, g, h); (3) urutkan item di tiap transaksi menurut frekuensi menurun (a, b, c, d, e).
  1. T1 {a,b}: buat node a, b; path null→a→b; count 1.
  2. T2 {b,c,d}: buat 3 node b,c,d; path null→b→c→d; count 1. Walau T1 dan T2 sama-sama punya b, path disjoint karena prefix berbeda. Tambahkan link antar b.
  3. T3 {a,c,d,e}: prefix a sama dengan T1 → path overlap, count a bertambah (a:2). Tambah link antar c dan antar d.
  4. Lanjutkan sampai semua transaksi terpetakan. Hasil akhir FP-Tree:
Aturan inti: kalau prefix sama → naikkan count node yang sudah ada; kalau beda → buat cabang baru dengan count 1. Selalu hubungkan node berlabel sama dengan pointer.

9. Algoritma FP-Growth

Tiga tugas utama

  1. Pembangkitan Conditional Pattern Base — subdatabase berisi prefix path (lintasan prefix) dan suffix pattern (pola akhiran), didapat dari FP-Tree yang telah dibangun.
  2. Pembangkitan Conditional FP-Tree — support count tiap item di conditional pattern base dijumlahkan; item dengan support count ≥ minimum support count dibangkitkan dengan conditional FP-Tree.
  3. Pencarian frequent itemset — bila conditional FP-Tree berupa lintasan tunggal (single path), frequent itemset diperoleh dengan mengombinasikan item pada conditional FP-Tree. Jika bukan single path, lakukan FP-Growth secara rekursif.

Sifat

  • Mengekstrak frequent itemset dari FP-Tree.
  • Algoritma bottom-up — dari leaf menuju root.
  • Divide and conquer: pertama cari frequent itemset yang berakhir di e, kemudian de, dst.; lalu d, kemudian cd, dst.
  • Pertama ekstrak prefix path sub-tree yang berakhir di item (set).

Setiap prefix path sub-tree diproses rekursif, hasil akhirnya digabung (merged). Mis. sub-tree untuk e dipakai mengekstrak itemset yang berakhir di e, lalu de, ce, be, ae; kemudian cde, bde, ade, dst.

10. Contoh: Conditional FP-Tree untuk e (min support = 2)

  1. Buat prefix path sub-tree untuk e.
  2. Cek apakah e frequent dengan menjumlahkan seluruh count pada garis putus-putus node e: 1+1+1 = 3 ≥ 2 → {e} diekstrak sebagai frequent itemset.
  3. Karena e frequent, cari frequent itemset yang berakhir di e: de, ce, be, ae secara rekursif. Untuk itu perlu conditional FP-Tree untuk e terlebih dahulu.
Conditional FP-Tree = FP-Tree yang dibangun bila hanya mempertimbangkan transaksi yang mengandung itemset tertentu (lalu itemset itu dibuang dari seluruh transaksi).

Cara membuat conditional FP-Tree untuk e

  1. Update support count pada prefix path agar menggambarkan jumlah transaksi yang mengandung e. Di contoh: b dan c di-set ke 1, a ke 2.
  2. Hilangkan node e (informasi tentang e tidak dibutuhkan lagi).
  3. Hilangkan item tak sering dari prefix path. b hanya punya support 1 (<2) → be tidak sering → b dibuang.
  4. Gunakan conditional FP-Tree e untuk menemukan itemset berakhiran de, ce, ae (be tidak dianggap karena b tidak ada di conditional tree e). Untuk tiap akhiran: cari prefix path, ekstrak frequent itemset, buat conditional FP-Tree, dst (rekursif). Mis. e → de → ade ({d,e}, {a,d,e} ditemukan frequent).

14. Checklist Persiapan UAS

  • ☐ Hafal rumus support, confidence, dan support × confidence.
  • ☐ Bisa membedakan antecedent vs consequent; consequent hanya 1 unsur.
  • ☐ Bisa menjalankan Apriori: $F_1\to F_2\to\dots$ sampai kosong; terapkan prinsip Apriori.
  • ☐ Bisa menjumlah 2-itemset ($\binom{n}{2}$ pasangan) dan menghitung jumlah rule ($2\times|F_2|$).
  • ☐ Bisa membangun FP-Tree: buang item < min, urutkan frekuensi menurun, tambah count bila prefix sama.
  • ☐ Bisa membuat conditional pattern base & conditional FP-Tree untuk suatu suffix.
  • ☐ Tahu alasan FP-Tree dibanding Apriori (tanpa candidate generation, hindari scan berulang).
  • ☐ Tahu best/worst case ukuran FP-Tree.
